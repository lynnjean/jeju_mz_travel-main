# 청년층 제주 관광 동향 대시보드

> **이 저장소에 포함되지 않은 것**
> - 원본 xlsx(`data/`): 출처 이용 조건을 확인하지 못했고, 일부 파일이 GitHub 웹 업로드 한도(25MB)를 넘습니다. 대시보드는 집계된 `data.js`만으로 동작합니다. 데이터를 다시 만들려면 이 폴더 바로 위에 `data/` 폴더를 두고 `python build_data.py`를 실행하세요(스크립트가 `../data`를 읽습니다).
> - 네이버 블로그 수집 결과(`reviews.js`, `naver_blog/raw/`): 다른 사람의 글 정보가 들어 있어 공개하지 않습니다. 그래서 9번 '온라인 후기'는 "데이터 없음"으로 표시됩니다. `naver_blog/`의 스크립트로 직접 수집하면 채워집니다.
> - 아래 설명의 `dashboard/` 경로는 이 저장소에서는 맨 위 폴더를 뜻합니다.

## 실행 방법
1. `dashboard/index.html`을 더블클릭해 브라우저(Chrome·Edge·Safari)에서 엽니다. 서버나 인터넷 연결 없이 동작합니다.
2. 원본 xlsx를 바꾼 경우에는 아래처럼 데이터를 다시 생성합니다(약 3분 소요).
   ```
   pip install pandas openpyxl
   cd dashboard
   python build_data.py
   ```

## 분석 보고서와 발표
- **분석 보고서(`#report`)**: 왼쪽 메뉴에서 열고 [PDF로 저장]을 누른 뒤, 인쇄 창의 대상을 'PDF로 저장'으로 선택합니다. 머리글과 바닥글 옵션은 끄는 것을 권장합니다.
- **발표(`#present`)**: 슬라이드 11장을 보여 줍니다. 조작 키는 ←/→ 또는 Space(이동), Home/End(처음/끝), F(전체 화면), N(발표 메모)입니다. 터치 화면에서는 좌우로 밀어 넘깁니다.
- 발표 화면의 차트와 숫자는 슬라이드를 열 때마다 움직이며 그려집니다. 보고서는 화면에서 스크롤할 때만 움직이고, PDF에는 최종 모습이 저장됩니다. 시스템의 '동작 줄이기'를 켜면 움직임이 꺼집니다.
- 두 화면 모두 대시보드에서 고른 기간과 연령·성별·지역 조건을 그대로 반영합니다.

## 필요한 파일
```
대시보드/
├─ data/                       원본 xlsx 7종 (읽기만 함, 수정하지 않음)
└─ dashboard/
   ├─ index.html               대시보드 화면 (필터, 차트, 계산 로직)
   ├─ data.js                  build_data.py가 만든 집계 데이터 (약 4MB)
   ├─ build_data.py            원본 xlsx → data.js 전처리
   ├─ lib/echarts.min.js       Apache ECharts 5.5.1
   ├─ lib/echarts-wordcloud.min.js  워드클라우드 플러그인 2.1.0
   └─ source/jeju_emd_2013.geojson  제주 읍면동 43개 경계 (southkorea-maps, 통계청 2013)
```

## 데이터별 기간과 집계 기준
| 데이터 | 기간 | 단위 | 연령 정보 | 사용 영역 |
|---|---|---|---|---|
| 제주 연령대별 방문 | 2024-01 ~ 2026-08 월별 | 명 | 있음 (10~70, 성별 M/W) | 3, 4, 5 |
| 제주 지역별 방문객(읍면동) | 2024-01 ~ 2026-08 월별 | 명 | 없음 | 6 |
| 제주 지역별 인기 장소 | 2024-01 ~ 2026-09 월별 | 도착 수 | 없음 | 7 |
| 비짓제주 검색어 순위 | 2024-01 ~ 2026-08 월별 | 수치 (단위 미상) | 없음 | 8 |
| 월별 입도 관광객, 국가별 외국인 입도객 | 2024-01 ~ 2026-08 | 명 | 없음 | 참고 |
| 입도 관광객 추이(일별) | 2024-01-01 ~ 2026-10-21 | 명 | 없음 | 참고 (월별 파일과 대조) |

- 위 네 데이터는 서로 집계 기준이 다릅니다. 한 달 기준으로 연령대별 방문객 합계는 약 330만~540만 명, 읍면동 43개 합계는 약 1,000만~1,660만 명, 월별 입도객은 약 83만~135만 명입니다. 따라서 서로 직접 비교하지 않습니다.
- 온라인 후기 데이터는 제공되지 않았습니다. 9번 영역은 "데이터 없음"으로 표시됩니다.

## 지도와 워드클라우드에 사용한 데이터
- **지도(6번)**: 「제주 지역별 방문객(읍면동)」의 읍면동명을 2013년 통계청 읍면동 경계와 이름으로 결합했습니다. 43개 읍면동이 모두 일치했습니다. 색상은 선택 기간의 월별 방문객 수를 합한 값입니다. 지표는 총 방문객, 내국인, 외국인 중에서 고를 수 있습니다.
- **워드클라우드(8번)**: 「비짓제주 검색어 순위」의 `지역명`(장소명)별 `수치`를 합한 값 중 상위 80개를 표시합니다. 같은 키(기준년월·분류명·지역명·주소)에 최대 7행이 있는데, 이 행들을 구분하는 컬럼이 없습니다. 그래서 행을 삭제하지 않고 모두 합산했습니다. 플러그인을 불러오지 못하면 자동으로 막대그래프로 바뀌며, 빈도 표는 항상 표시됩니다.

## 전처리 원칙
- 원본 값은 바꾸지 않고 합산만 합니다. 결측값·이상값 후보도 삭제하지 않습니다.
- 인기 장소는 용량 때문에 전체 기간 관광객 도착 수가 300 이상인 장소 7,701개만 data.js에 담았습니다. 이는 전체 도착 수의 90.7%에 해당합니다. 표시된 순위 중 값이 300 미만인 행에는 †와 경고가 표시됩니다.
- 장소명 일부는 엑셀에서 시간·날짜·숫자로 바뀐 상태로 저장되어 있습니다(예: `11:11:00`, 48행). 문자열로만 바꿨으며, 원문은 따로 확인해야 합니다.

## 온라인 후기 연결 (네이버 블로그 검색 API, 선택 사항)
`reviews.js`가 없으면 9번 영역은 "데이터 없음"으로 표시됩니다. 아래 순서대로 실행하면 9번 영역이 실제 수집 데이터로 채워집니다.

1. **API 키 발급 (NAVER API HUB)**: 2026-07-31부터 네이버 개발자센터에서는 검색 API를 새로 신청할 수 없습니다. 대신 네이버 클라우드 플랫폼의 NAVER API HUB에서 발급받습니다.
   - https://www.ncloud.com 에 가입하고 콘솔에 로그인합니다.
   - Menu → All Services → Application Services → **NAVER API HUB** → 신청하기를 누릅니다.
   - Subscription → [서비스 이용 신청]을 누르고 약관에 동의합니다.
   - Application → [Application 등록]에서 **블로그 검색**을 선택하고 이름을 입력해 등록합니다.
   - 발급된 Client ID와 Client Secret을 아래 3번에 사용합니다.
   - 2026-07-25 이전에 개발자센터에서 발급받은 키가 있다면 발급 후 1년 동안 쓸 수 있습니다. 이 경우 `export NAVER_API=legacy`를 추가로 설정합니다.
   - 요금: 공식 문서 기준 현재 한시적 무료이며, 검색 API는 월 775,000건까지 호출할 수 있습니다. 유료로 바뀌면 별도 공지된다고 합니다.
2. **검색어 확인**: `naver_blog/queries.txt`를 엽니다. 한 줄에 검색어 하나이며, 검색어당 최대 1,000건을 수집합니다.
3. **수집**:
   ```
   cd dashboard/naver_blog
   export NAVER_CLIENT_ID=발급받은ID
   export NAVER_CLIENT_SECRET=발급받은Secret
   python3 collect.py
   ```
   결과는 `naver_blog/raw/blog_수집시각.jsonl`에 API 응답 그대로 저장됩니다.
4. **분석 데이터 생성**: `python3 build_reviews.py`를 실행하면 `dashboard/reviews.js`가 만들어집니다. 그다음 index.html을 새로고침합니다.
5. **주제 분류 수정**: `naver_blog/topics.json`의 키워드를 고친 뒤 4번만 다시 실행합니다.

알아 둘 점
- API는 제목과 요약문(1~2문장)만 제공합니다. 본문은 수집하지 않습니다.
- 주제 집계는 키워드가 들어 있는지만 보는 방식이며, 감성 분석이 아닙니다. 불편 사항은 불만 표현(예: "주차가 힘들")으로만 집계하지만 오탐이 있을 수 있으므로, 9번 영역에서 항목을 클릭해 근거 글을 직접 확인해야 합니다.
- 네이버 검색은 '20대'를 '20'과 '대'로 나눠 찾기 때문에 "20개월 아기랑" 같은 글도 섞입니다. 그래서 대시보드는 기본으로 다음 세 조건을 모두 적용합니다. ① 광고성 표시가 없는 글 ② 20대 관련 단어(20대·대학생·청춘 등)가 있는 글 ③ '제주'가 들어간 글. 세 조건은 각각 체크박스로 끄고 켤 수 있습니다.
- 2026-11-02 수집 결과(검색어 5개 × 1,000건, 고유 글 4,289건)를 보면 요약문에는 불편 표현이 거의 없습니다(주제별 최대 4건). 불편 요인은 이 데이터로 판단하기 어렵습니다.
- 작성자 연령은 알 수 없습니다. 20대가 쓴 글이라고 단정하지 마세요.
- 광고 문구("원고료", "협찬" 등)가 요약문에 드러난 글만 광고성으로 표시됩니다. 본문 끝에만 광고 표기가 있는 글은 걸러지지 않습니다.
- 대시보드의 기간 필터는 블로그 게시일(postdate)에 적용됩니다.
- SSL 인증서 오류가 나면 `pip3 install certifi`를 실행하거나, macOS의 '응용 프로그램 > Python 3.x > Install Certificates.command'를 실행합니다.
